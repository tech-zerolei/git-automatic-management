# 使用指南

适用：本地只读版 **0.1.0**。建议不是兼容性证明，工具不执行项目发布。

## 安装与启动

**DEB用户：** 从Releases下载安装包，用 `sudo apt install ./git-version-planner_0.1.0-1_all.deb` 安装，再从应用菜单或 `git-version-planner` 启动。不需要运行下面的源码install.sh。[DEB详细说明](DEB.md)。

下载ZIP解压或手动克隆本工具，进入根目录运行 `./start.sh`。需要Linux图形桌面、`/usr/bin/python3`、`/usr/bin/git`、`/usr/bin/bwrap`、`/usr/bin/zenity`。优先以Chrome应用窗口打开，否则用xdg-open调用默认浏览器。无需pip/npm，无运行时下载。

`./install.sh` 通过 `xdg-user-dir DESKTOP` 写入当前用户桌面入口。内容相同可重复安装；不同内容/符号链接拒绝覆盖。无需sudo，不安装系统服务。移动工程后需处理旧图标再安装。

ZIP解压丢失执行权限时：

```bash
chmod +x start.sh install.sh
./start.sh
```

仅输出会话地址、手动打开：`./start.sh --no-browser`。固定端口：`./start.sh --port 8765`，默认随机端口。完整会话地址的片段是随机凭据，不要分享。不支持跨机器访问。

## 1. 读取本地工作树

点击“选择仓库”，或输入绝对路径再“读取”。可以选择工作树内目录，程序解析实际根目录；不递归扫描主目录或其他项目。普通和linked worktree可用；bare不支持。无HEAD可显示空状态，但不能规划版本。

| 信息 | 解释 |
| --- | --- |
| 分支/HEAD | 本地分支、detached或尚无提交 |
| 暂存/未暂存/未跟踪 | 条目数量，不是代码行数 |
| 冲突 | 未解决条目，存在时要求复核 |
| upstream领先/落后 | 相对本地跟踪引用，不联网更新 |
| 采集时间 | 快照时间，不代表持续监控 |

子模块内部工作区不读取；主项目历史仍作为主项目分析。未提交文件不进入版本计算，只显示风险。

## 2. 确认基线

稳定候选接受严格SemVer，例如 `1.2.3`、`v1.2.3`，仅小写v。预发布或build标签不自动作为稳定基线。选择完整引用并勾选确认，展开标签证据查看对象/可达性。标签不证明已发布，签名未验证。

范围为固定HEAD可达提交集合减固定基线可达集合，每个OID只计一次，不按日期猜测。

无可达稳定标签时手动输入首次版本，例如 `0.1.0`，不带v或前导零，再确认。历史不是单一完整根或首次版本含预发布/build时进入复核。程序不猜初始版本。

修改基线/首次版本输入会清除原计划和确认。

## 3. 生成与理解建议

支持例如：

```text
fix: 修复导出
feat(ui): 增加预览
feat!: 调整公共接口

fix: 清理接口

BREAKING CHANGE: 删除旧接口，请迁移到新接口
```

最高信号决定递增：

| 信号 | major>=1 | major=0 |
| --- | --- | --- |
| breaking | major+1，minor/patch归零 | minor+1，patch归零 |
| feat | minor+1，patch归零 | minor+1，patch归零 |
| fix | patch+1 | patch+1 |
| 无新增提交 | 无需升级 | 无需升级 |

- `suggested`：规则给出候选，不是发布批准。
- `needs_review`：保留暂定计算和证据，无确定候选；先处理歧义。
- `no_release`：没有形成升级的规则结果，结合提交和证据理解。

非规范、docs/chore/refactor等未映射类型、merge/revert、重复归一标签、占用候选、预发布/build、冲突可能触发复核。不删提交、不用AI猜兼容性。CI/测试/发行状态未知。

## 4. 人工复核

填写非空理由，可选输入调整后完整版本，再“确认当前计划”。版本必须高于基线且不占用已有本地标签。人工版本单独保存；机器建议、冲突和待复核项保留，不视为发布授权。

刷新、仓库变化使旧确认失效。多个窗口共用会话时，预览/导出必须匹配当前显示计划指纹；其他窗口更新计划后，旧窗口应重新生成和复核。

## 5. 预览与导出

选择Markdown或JSON，预览后导出。文件选择器不可用时，界面提供绝对路径输入。

Markdown含状态/规则/HEAD/快照/基线/候选/风险/复核/类型分组及完整BREAKING正文和OID。JSON保留完整结构，当前未承诺跨版本稳定公共API。

1. 必须绝对路径，按格式补 `.md`/`.json`。
2. 拒绝所选/关联/其他Git工作树和Git元数据目录；拒绝符号链接路径。
3. 已有文件一律拒绝，请选新文件名。
4. 目标文件系统需支持O_TMPFILE无名临时文件及硬链接；不支持则失败。
5. 导出时不要移动目录。检查发现移动会取消并撤销本次目标，但不能阻止任意同用户进程移动文件系统目录。
6. 保存选择期间仓库或计划变更也会拒绝，避免保存未经该窗口确认的另一计划。

报告包含提交消息/引用/OID，只在用户选定本地目标保存，需自行保管。

## 6. 排障

| 现象 | 处理 |
| --- | --- |
| 缺少Python/Git/Bubblewrap/Zenity | 安装发行版组件，不关闭隔离绕过 |
| bwrap不能创建隔离 | 检查系统命名空间/容器限制，本版失败不降级 |
| clean/process拒绝 | LFS或自定义转换器不支持，不建议随意删除项目配置 |
| include/扩展/部分克隆/浅历史拒绝 | 选择本版支持且完整的已有本地仓库 |
| replace/graft/alternates拒绝 | 有替代历史/对象依赖，不能当原始完整图 |
| 元数据符号链接拒绝 | 不支持该布局，不要盲改真实Git元数据 |
| 无HEAD/非仓库/bare | 选择有提交的普通工作树，工具不init/commit |
| 超30秒/16MiB/5000项 | 拒绝不完整结果，无调高上限的配置入口 |
| 非UTF-8元数据 | 不能无损显示，明确拒绝 |
| 仓库变化/计划更新 | 刷新、重新确认基线、生成并复核 |
| 导出失败/已有文件 | 仓库外可写目录、新文件名、支持O_TMPFILE的本地文件系统 |
| 桌面无法启动 | 允许启动、检查原目录仍在；终端运行start.sh看错误 |
| 关窗后进程仍在 | 用右上角退出；否则30分钟无请求后退出 |

## 升级与卸载

无自动更新器，手动获取维护者发布的新源码，退出后更新，重启重选。卸载先退出，删除自己安装的桌面入口，再按需删除工程。无hook/系统服务/配置缓存；导出报告另行管理。

## 当前没有的入口

GitHub密钥、自动提交/发布、CI、Codex插件和多包配置均不可用，不能靠隐藏参数开启。未实现项没有受支持用法，见[功能对照](FEATURES.md)。
