## 2. 数据流与执行边界

```text
用户启用批准范围
  → HostAdapter 提供实际入口与已验证触发，选择本地 / GitHub 来源
  → GitHub 模式每次经 CredentialBroker 明确选择 PAT / SSH 与保管方式，确认目标，直接远端规划
  → DetectionCoordinator 合并任务、分配代次
  → GitReadAdapter 或 GitHubReadAdapter 能力 / 权限检查与最小元数据读取
  → RepoSnapshot + 完整性 / 陈旧状态
  → ReleaseAnalyzer 固定 B/H、规则和提交集合
  → VersionPlan + 下一版本与变更说明 + 来源 / 证据 + 待复核项 + 仓库风险
  → PlanReview 用户审查 / 手动调整
  → 用户另行选择外部目标后 ExportWriter 导出
```

### 2.1 最先验证的技术风险

1. 核实具体 Codex 载体的实际入口、触发、Git 子进程、取消、外部导出和非模型安全凭据输入能力；不能假设安装 Skill 就有持续监听。若缺能力则明确禁用 / 降级并重评范围。
2. Git 版本和能力能否实现离线、无可选索引刷新与无外部助手读取。SPEC 第 14 节官方文档仅是依据，不是本机验证结果。
3. linked worktree 的实际 Git 目录可能不位于工作树内；批准工作树意味着是否允许访问其关联元数据必须在发现边界里显式说明，不扩大到任意其他路径。
4. 仓库配置 / 环境变量可能改变 Git 行为；受控环境必须排除不可信覆盖路径、外部监控、pager、隐式补对象及意外访问其他仓库。不得改用户配置来“修好”安全问题。
5. 报告写入有路径解析与竞态风险；确定宿主可提供的安全目标解析 / 文件句柄 / 原子替换方式。无法确保约束时拒绝导出，不降低到危险写法。
6. 核验 GitHub 认证类型、端点 / Git 读取操作与权限、主机验证、重定向、分页完整性、限流和取消；SSH 若无法在不 clone / fetch 的边界内提供所需提交图，明确限制，不能静默改走 PAT 或下载仓库。
7. 凭据入口 / 保管与 Codex 模型上下文必须隔离；仅允许连接适配器短时使用必要秘密，不以脱敏日志代替传输审计。无安全凭据库时不能回退普通设置文件。

### 2.2 Git 访问建议

- 官方命令语义参考 SPEC 的 [S1]、[S2]、[S3]、[S6]。只为已核实能力建立读取操作；不预先声称某个最低 Git 版本适用。
- 通过可信可执行文件路径与参数列表启动，所有 refs 和路径先解析 / 校验，不直接拼接用户字符串、提交消息或 shell 命令。
- 机器状态采用稳定格式与 NUL 分隔；对象 ID 和路径按 Git 返回值处理，不假设 40 字符哈希或每行一个文件。
- 评估并验证禁用可选锁、lazy fetch、pager、外部 fsmonitor 等实际行为；仅禁用锁不等于阻止网络或助手执行。
- 提交图处理须明确 replace refs、graft / shallow 边界和缺对象的语义。无法保证原始完整图时返回不完整 / 不支持，不静默使用改写图得出正式版本。
- 使用只读元数据读取，不运行 hooks、外部 diff / textconv、源码构建、安装脚本或仓库内可执行文件。

## 6. 配置、交付与恢复

- 当前没有安装包、应用标识、依赖清单或发布渠道；不得宣称可安装或已上架。
- 首次正式安装前审查权限、宿主兼容、Git 能力矩阵、配置默认值和日志脱敏，不要求用户全局降低 Git 信任设置。
- 禁用 / 卸载释放监控、子进程、连接请求、活动会话秘密和缓存；断开与单独删除已保存凭据分开。持久库的具体生命周期由 Q-004 提案，删除只限应用管理项并报告失败；不删除报告、既有 SSH 私钥 / 代理身份或擅改 Git 配置。本地清理不等于 GitHub 服务端撤销。
- 运行错误只停止受影响仓库任务；重试遵循预算，不无限重启。错误日志只记录必要阶段和代码，不带原始 token / 私有路径。
- 当前无数据库或版本文件迁移；若批准宿主设置持久化，应设计 schemaVersion 与无效配置恢复，不能将“无迁移”当作未来永远不需要。
- 本轮仅修订文档，不访问真实远端或索取密钥。未来实施按批准范围支持 GitHub 读取；远端写入、生产发布、下载安装包仍需另行授权。
