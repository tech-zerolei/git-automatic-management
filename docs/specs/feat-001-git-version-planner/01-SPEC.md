### 0.2 已确认方向与授权边界

2026-10-25，先前触发、模型边界、SemVer、Conventional Commits、基线确认方式、稳定版映射、单一发布单元和 bare-or-v 继续有效；本轮补充 Q-003 的三个独立选择：`zero_major=conventional-zero`、`prerelease=review-prerelease`、`initial_version=manual-initial`。用户随后授权其余细则由助手直接选择。以下不构成产品实现批准、技术能力验证或实施授权：

- 在工作开始与结束节点检查，并保留手动刷新；不选择持续监控或轮询。真实生命周期事件和可靠接入方式归 Q-004 核验，缺失时必须显示自动检查不可用，不能把未触发当作检查成功。
- 先由确定性规则提出候选版本，再由用户针对当前输入指纹显式复核确认。保留机器建议、人工选择、理由与冲突；来源、规则或输入变化立即作废原确认。确认不等于发布授权，也不证明历史完整或 API 兼容。
- 仅允许经过白名单、脱敏与校验的聚合统计和版本候选进入模型；原始提交消息、代码、路径、凭据、仓库可识别信息和完整证据不得默认进入模型。完整计划与证据保留在非模型路径，变更说明采用确定性非模型生成与单独核验的非模型展示 / 导出。
- 采用 SemVer、Conventional Commits，以及建议可达发布标签后人工确认基线；不按日期或字符串猜测基线，不重写历史。
- 已确认稳定版（major >= 1、非预发布）fix → patch、feat → minor、breaking → major，多信号取最高级，升级高位时低位归零；0.x 非预发布采用 fix → patch、feat → minor、breaking → minor，多信号取最高级，高位递增时低位归零；单一选定项目统一版本；标签仅接受裸版本或小写 v 前缀。
- 预发布相关规划一律进入 needs_review，不自动递增预发布标识、不自动转稳定版；没有可用稳定基线时不猜测初始版本，必须由用户输入并确认合法的 initialVersion。未知 / 未映射类型、非规范提交、merge、revert 或冲突不得静默丢弃，均保留证据并进入复核；merge 自身不产生默认 bump，revert 不自动抵消或生成负 bump。
- 仅接受裸版本或小写 v 标签；附注 / 轻量标签都可作为候选证据，但签名状态只展示、不作为信任证明；包含 build metadata、重复归一到同一版本或同一版本对应多个对象时不自动择一，进入复核。人工覆盖必须有非空理由并通过 SemVer、基线 / 初始版本、冲突和当前指纹校验，不能抹去复核项或变成发布授权。
- 保留本地模式、PAT / SSH 分别支持、直接远端规划与每次选择保管方式；安全入口、远端图完整性、生命周期与模型隔离仍待 Q-004 验证。
- 本轮只修订文档，不连接仓库、不输入或保存凭据、不传输仓库数据、不 clone / fetch、不创建后台任务、不写 Git、不发布、不实施插件。

## 1. 问题与目标

### 1.1 问题

使用者希望减少手动检查仓库状态和整理发布版本的工作。当前痛点的频率、耗时和错误率未提供，不编造收益数据。插件应回答：当前在什么仓库、发生了什么变化、相对哪条基线分析、下一版本为何这样建议、哪些地方仍需人工判断。

### 1.2 成功判据

| 目标 | 可观察结果 | 对应需求 | 验证方式 |
| --- | --- | --- | --- |
| 自动发现并反映仓库状态 | 在允许范围与已确认触发策略下更新状态；无仓库、无提交、无权限均有明确结果 | REQ-001、REQ-002、REQ-003、REQ-005 | 本地隔离夹具与宿主集成验证 |
| 版本建议可解释、可复现 | 给出固定 HEAD、基线、提交证据、规则版本和阻塞原因；不从不完整输入生成确定版本 | REQ-006、REQ-007、REQ-008、REQ-009、REQ-010 | 固定历史夹具与结果断言 |
| 不越权操作用户仓库 | Git 采集本地且不自动联网；导出显式选择；数据进入 Codex / 模型的范围单独确认；不自动发布 | REQ-012、REQ-013、NFR-001、NFR-002 | 区分 Git 子进程与宿主的数据通道后分别审计 |

性能收益与版本决策准确率的量化目标暂无数据，不能当作已承诺指标。

## 2. 范围与非目标

### 2.1 建议本次范围

1. 提供本地模式与可选 GitHub 连接模式；本地模式无需 GitHub 凭据即可使用。一次只分析明确选择的单一发布单元，不自动枚举账号下所有私有仓库。
2. 在工作开始与结束时检查并保留手动刷新；Q-006 方向已确认，真实接入能力待 Q-004 验证。GitHub 请求仅限用户启用的连接、仓库和已批准读取用途，不授权持续监控 / 轮询。
3. 当前 Git 状态、可达版本标签、基线到目标提交的变更信号。
4. 下一版本建议与变更说明草稿、证据和风险清单；人工调整与带快照标识的本地报告导出。不规划未来需求与发布日期。
5. 本地 Git 只读与 GitHub 受限只读访问、凭据保护、异常恢复、确定性和 Codex 接入验证；GitHub 首版分别支持 PAT 和 SSH、直接远端规划，每次连接选择会话使用或系统安全凭据库。Q-007 至 Q-009 的使用方向已定，技术能力归 Q-004，宿主 / 模型数据单独受 Q-005 约束。

### 2.2 明确不做

- 不自动执行 clone、fetch、pull、push、commit、reset、clean、stash、checkout、tag、rebase、发布或远端写操作；开启 GitHub 连接不等于允许这些动作。
- 不扫描整台机器、主目录或未由用户选择的仓库；不安装常驻守护进程或定时任务。
- 不把未提交文件内容当作已发布变更；不默认读取源码全文或将数据送到模型服务。
- 没有对应范围、固定引用和采集时间的实际远端证据时，不声称远端已同步；GitHub 连接成功也不证明 CI 通过、包已发布或实际 API 向后兼容。
- 不索取用户在聊天中粘贴真实密钥；不将密钥写入规格、仓库配置、明文文件、日志、导出或模型上下文，不自动申请写权限。
- 不提供多包独立版本、自动合并发布、跨仓库版本依赖求解或自动回退。
- 不在未收到未来需求和资源约束时生成真实产品路线图、承诺日期或发行里程碑。

### 2.3 后续候选，不构成本次承诺

多包 monorepo、预发布渠道自动递增、版本文件写入、changelog 写回、授权 clone / fetch、CI 状态集成、其他代码托管平台、API 差异分析、可选 AI 辅助摘要、未来需求路线图。GitHub 凭据连接已进入本次方向，但不等于上述功能获批；额外联网用途、写仓库或模型接入仍需另行确认。

## 3. 角色、场景与规则

### 3.1 角色与权限

| 角色 | 可以做 | 不可以做 | 依据 |
| --- | --- | --- | --- |
| 使用者 / 维护者 | 选择有权访问的工作区，启用检测，审查建议，输入人工理由，导出报告 | 借插件绕过文件权限、仓库信任或宿主授权 | 宿主权限与操作系统已有权限；具体信任机制待 Q-001 |
| 插件 | 在批准范围读取本地或已连接 GitHub 的必要元数据，计算建议，维护受限会话状态 | 越权访问仓库、修改仓库、泄露密钥、向未授权模型 / 第三方外发元数据或声称获得人工批准 | REQ-013、REQ-017 至 REQ-019 与非功能约束 |
| 发布负责人 | 在插件之外确认版本、执行实际发布 | 将“建议”直接视为发布授权 | 当前方案不包含发布执行器 |

不建立独立账号系统；GitHub 连接使用用户批准的外部凭据。具体认证机制待确认，不能推定允许向插件运营方中转凭据或托管私钥。

### 3.2 主场景

1. 使用者选择本地模式，或主动进入 GitHub 连接流程；后者先选择经支持的认证类型、目标仓库与读取用途，经安全入口提供凭据，不通过对话正文输入。
2. 插件发现候选仓库，使用者选择目标；展示工作树、分支 / HEAD、变更与数据新鲜度。
3. 插件在已确认触发策略下自动重新检测；手动刷新可独立使用，暂停后不再发起新的自动检测。
4. 使用者请求版本规划；本地模式分析所选工作树，GitHub 模式直接以选定远端仓库为来源，无需先创建本地工作树；冻结带来源标识的快照与固定对象，显示候选基线和筛选原因。读取能力不足则明确阻塞，不静默混用来源、改用另一凭据或 clone / fetch。
5. 基线和策略充分时分析提交，给出候选 bump、候选版本、变更分组、风险与待复核项。
6. 证据不足时显示待确认原因，保留能确定的事实，但不输出“确定可发布”结论。
7. 使用者可进行显式人工调整并导出报告；仓库变化会使旧建议标为陈旧，人工确认不得跨快照自动沿用。

### 3.3 状态与不变量

| 对象 | 合法状态 / 转换 | 不变量 |
| --- | --- | --- |
| 检测会话 | 未启用 → 检测中 → 可用；可用 ↔ 刷新中；任意运行态可暂停、停止或报错 | 暂停后不新增自动任务，停止 / 关闭工作区后释放监控；旧请求不能覆盖新请求 |
| 快照质量 | 完整 / 不完整 / 陈旧；每个快照带工作树身份与采集代次 | 多命令采集不宣称文件系统原子快照；变化无法稳定采集则标陈旧或不完整 |
| 版本计划 | collecting → needs_review / suggested / no_release；任一结果可变 stale | suggested 只表示规则计算完成，绝不表示已批准或已发布 |
| 人工复核 | 未复核 → 对当前指纹已复核；指纹变化则失效 | 版本、范围、分类或策略发生变化均不能无提示继承旧确认 |
| 本地报告 | 预览 → 选择目标 → 写入成功或失败 | 不覆盖未授权目标，不写入工作树或 Git 元数据目录，不把导出失败显示为成功 |
| GitHub 连接 | 未配置 → 待确认 → 连接中 → 已连接 / 失败；可断开、失效或更换凭据 | 未启用不请求；连接成功绑定可访问的具体仓库，不等于授权发布；断开后停止新请求，迟到结果不恢复连接 |

### 5.2 Git 状态与触发策略

- 建议使用适合机器解析的状态接口；Porcelain v2 可输出分支与工作树信息，NUL 分隔用于特殊路径处理 [S1]。界面不把原始 Git 输出直接当 HTML。
- upstream 信息缺失、跟踪引用缺失和领先 / 落后未知是不同状态；本地跟踪引用不代表刚查询过服务器。
- Q-006 已选择工作开始与结束节点检查，并保留手动刷新；不选择持续文件监听或轮询。开始 / 结束事件的精确定义、工作取消 / 异常退出时的行为和宿主真实集成能力由 Q-004 技术提案验证，不以普通 Skill 读取代替生命周期事件。
- 节点合并、去重窗口、取消和有界运行预算仍待 Q-004；未支持、事件丢失或调度失败必须显示未执行 / 自动检查不可用，不报成功，不静默改为常驻、轮询、后台服务、定时任务或全局 Git hook。
- 两节点之间的仓库变化不保证实时反映；每次节点检查 / 手动刷新重新验证来源与相关元数据，旧缓存只可标注陈旧，不能当作新检查结果。
- 建议每个工作树最多一个进行中的采集和一个合并后的最新待处理请求；没有变化的结果不重复弹通知。此为建议并发策略，不是已测性能承诺。
- 暂停停止新的自动调度；用户主动刷新是独立动作。停止或关闭工作区取消当前任务、清理队列和订阅，迟到回调不得复活会话。

### 5.3 发布基线候选

已确认基线方向：单一发布单元，标签接受裸版本或小写 v 前缀，以 SemVer 比较合法可达稳定标签候选，建议后由用户显式确认；不是自动采用“最新标签”。本版直接采用保守规则：预发布 / build metadata 不自动作稳定基线，签名状态只作展示，重复归一或同版本多对象不自动择一，标签语法不证明真实发布：

下列“本地”算法适用于本地模式。Q-008 已确认直接分析 GitHub：远端模式用选定来源的固定仓库 / 引用 / 对象代替本地身份，仍须证明可达性和完整集合；API 分页、比较结果或标签列表本身不视为证明。不能用远端 Release 时间或简单提交列表替代下列条件；适配能力不足返回 needs_review，不隐式克隆 / fetch，未验证通道不得标为可完整规划。

1. 仅使用本地、可解析到提交、属于选定发布单元且可达目标 HEAD 的稳定标签；同时处理轻量和附注标签，不把标签日期当成版本高低。预发布标签和含 build metadata 的标签保留为证据，但不自动作为稳定基线。
2. 已确认仅接受裸版本或小写 `v` 前缀，例如 `1.2.3` / `v1.2.3`；其他前缀不自动纳入。比较时去除被允许的小写 v，但保留完整标签引用及对象。裸版本和 v 前缀同时存在造成重复归一、同一版本指向多个对象或 build metadata 造成优先级并列时，进入复核，不自动去重择一；签名状态只展示，不推定发布可信。
3. 在已确认发布范围内，对完整可达合法稳定标签按 SemVer 优先级建议候选，向用户展示原因，必须显式确认后才作为 B；缺失 / 歧义 / 未确认时不猜测 B。若没有可用稳定标签，则不自动创建 0.1.0 或 1.0.0，而进入首次版本流程。
4. 手动基线必须解析为完整本地引用及提交，并满足范围和可达性约束；输入不能直接拼接命令字符串。
5. 不可达的更高标签不作为当前基线，但若下一版本在任何本地相关标签中已被占用，显示版本冲突，不自动跳号。
6. 无标签、只有预发布标签、版本文件与标签不一致或基线不可用时，用户必须在非模型界面输入并确认合法 initialVersion；若仓库历史只有一个完整根且提交范围可证明，则以该根之前的空集合作为首次规划起点，否则仍 needs_review。没有 initialVersion、存在多个根、历史不完整或目标版本占用时不生成确定候选；单一发布单元不自动扩展为 monorepo 多包独立规划。

### 5.4 提交集合与分类

- 固定基线对象 B 和目标对象 H，分析集合为“从 H 可达、但从 B 不可达”的提交，即 Git 的双点范围语义 [S3]。不按提交时间筛选，不默认只看 first-parent。
- 按对象身份去重；merge 及其父链的提交不能重复计数。普通 merge 消息不是可自动忽略的业务变更证据；对未分类消息显示复核，不静默扩大排除规则。
- 不读取工作区源码全文推断未来发布；dirty 仅产生“未提交内容未纳入”风险，不改变已提交集合的计算。
- 已选择 Conventional Commits，参照既有 1.0.0 规范识别 `fix`、`feat`、`!` 及合法 breaking footer 等描述信号 [S5]；规范信号与项目递增策略分离。major >= 1 与 0.x 的稳定版映射均已确定；预发布相关信号不自动递增。
- 其他合法 type 不自动升级为 patch；非规范消息、未映射 type、revert、merge、混合 / 自相矛盾证据保留并进入人工复核。merge 提交自身不产生默认 bump，若其消息有合法 bump 信号则保留信号但计划仍需复核；revert 不自动抵消、降级或生成负 bump。不得仅通过标题包含 `break` 等单词判断 breaking。
- 分类属于“提交描述声称的意图”，不是 API 差异证明。用户可逐条复核，系统保留修改前后的理由与对应对象。

### 5.5 下一版本建议

SemVer 方案、Conventional Commits 分类、稳定版与 0.x 映射、预发布复核、首次版本手动输入、单一发布单元和 bare-or-v 均已收敛。稳定版规则为：`major >= 1` 且非预发布时 fix → patch、feat → minor、breaking → major；0.x 且非预发布时 fix → patch、feat → minor、breaking → minor；多信号取最高级，升级高位时低位归零。无提交 no_release；未知 / 未映射 type、非规范、merge、revert、预发布、build metadata、重复归一、同版本多对象或冲突为 needs_review，不自动 patch、不自动抵消、不自动升级预发布号。SemVer 语义参照 [S4]。

发布域已确认为单一发布单元，标签前缀已确认为裸版本或小写 v。仅当完整证据、固定稳定基线或已确认 initialVersion、适用规则和当前指纹齐备时才可产生 candidateVersion；有缺口仍保持 needs_review。首次版本只接受用户显式输入并确认的 initialVersion，不自动猜测 0.1.0 / 1.0.0。下表是隔离规则样例，不是实际产品执行或真实仓库结果。

| 输入条件 | 机器输出 | 额外状态 |
| --- | --- | --- |

**独立模型投影 `ModelSummaryProjection`（Q-005 已确认，具体隔离能力待 Q-004）：**

### 5.7 导出与数据生命周期

只允许用户显式指定的、位于受管工作树与真实 Git 元数据目录之外的文件目标；linked worktree 的共享目录也在禁止写入范围。目标为符号链接或无法确认边界时拒绝，不悄悄跟随；覆盖已存在文件需要单独确认。

建议采用同目录临时文件再原子替换，成功后才返回完成；无安全写入保障时拒绝而非退回不安全写法。导出只写报告，不写版本文件。默认原始元数据仅留在会话内存；如需持久化设置 / 缓存，存储位置、保留期与清除方式待 Q-004，未确认不擅自设定期限。

## 8. 验收标准

以下均是待执行目标，不是通过记录。拟采用的配置与主机平台尚未确认，所涉场景必须在基线就绪后执行。所有测试数据均为隔离合成夹具。

AC-001 至 AC-005 的工作树语义适用于本地模式；GitHub-only 来源的本地状态为 not_applicable 而非 clean / 空变更，本地能力不能因此整项跳过。Q-008 已确认直接远端规划，AC-006 至 AC-011、AC-015、AC-016 和确定性 / 性能用例必须补齐远端等价夹具，分别覆盖 PAT 与 SSH；保持原编号，结合 AC-024 验证固定来源、可达性和完整集合。不能以仅认证成功、API 返回成功或 needs_review 的安全降级证明全部规划能力已实现。

### AC-001：明确范围的仓库发现

- 关联需求：REQ-001。
- Given：启用范围内有普通目录、一个仓库及其子目录、嵌套仓库、已初始化子模块和两个 linked worktree；范围外另有仓库。
- When：按已确认发现策略检测并分别选择结果。
- Then：只列出边界内目标；同一工作树子目录去重，子模块 / 嵌套仓库分别标识，共享对象库的 worktree 不误合并；普通目录无异常。
- 验证：对比独立 Git 身份探测与候选清单；保留发现边界及去重证据。扫描策略未定时本项阻塞。

### AC-002：工作树状态不冒充远端事实

- 关联需求：REQ-002。
- Given：依次配置正常分支、detached、无 upstream、丢失跟踪引用，以及合成暂存 / 未暂存 / 未跟踪 / 冲突状态。
- When：采集状态；另在测试远端新增提交但本地不 fetch。
- Then：分类与真实本地 Git 状态一致；未知计数为未知，不为零；ahead/behind 注明依据本地引用，不声称检测到尚未获取的远端提交。
- 验证：状态对象与 UI 标签断言；保留网络无访问记录。

### AC-003：启停、事件合并与降级

- 关联需求：REQ-003。
- Given：已选择开始 / 结束节点加手动刷新，Q-004 的真实事件、合并窗口、预算与失败语义已经核实；另有宿主不支持节点的环境。
- When：开始 / 结束节点重复或重叠到达，暂停、手动刷新、恢复、事件失败、停止及异常退出。
- Then：仅允许的节点自动调度；重复有界合并，暂停不自动调度但可手动刷新；未支持 / 未触发 / 失败明确显示未执行，不当成功；停止后无新任务或迟到复活，不创建轮询 / 后台任务。
- 验证：受控事件与真实宿主集成记录分别验证开始 / 结束 / 失败；未知能力和参数前不得填通过。

### AC-004：并发、身份与陈旧结果

- 关联需求：REQ-004。
- Given：同一对象库的工作树 A / B，各有独立分支；A 的旧采集比新采集晚返回。
- When：开始 / 结束与手动刷新重叠，切分支、更改来源 / 连接代次、标签、基线、规则或人工输入，取消并切换工作树。
- Then：A / B 状态不串用；只发布当前代次完整结果；旧人工复核失效；不稳定快照标为陈旧或不完整。
- 验证：受控乱序执行与指纹断言，记录旧结果被拒绝的证据。

### AC-005：缺少 Git 或历史时不伪造结果

- 关联需求：REQ-005。
- Given：Git 缺失 / 能力不足、不可访问仓库、信任拒绝、bare、无提交、浅历史、缺失对象分别独立作为输入。
- When：请求检测和规划。
- Then：返回对应明确原因；无 HEAD 不生成提交范围；历史不全不宣称完整；不改信任配置、不安装 Git、不发起补对象网络请求。
- 验证：隔离夹具及失败注入，记录错误码、文件和网络审计。

### AC-006：基线按版本与可达性选择

- 关联需求：REQ-006。
- Given：已选单一发布单元，分别有裸版本 / 小写 v 可达稳定标签 1.9.0 与 1.10.0、预发布标签、build metadata 标签、不可达 9.0.0、其他前缀、附注 / 轻量标签、重复归一版本、同版本多对象和非法标签；这些情况分开测试。
- When：请求候选基线，分别不确认 / 显式确认 / 手选合法或非祖先标签，并模拟无稳定标签、initialVersion 缺失或已确认、多个根和不完整历史。
- Then：在完整证据下建议 1.10.0，不按字符串或日期选；预发布 / build metadata 不自动作为稳定基线，其他前缀不自动纳入，语法不证明发布；显式确认前不采用 B 或生成确定版本，确认绑定完整引用 / 对象与当前来源指纹；无稳定基线时仅接受用户确认的 initialVersion，其他缺口均给原因和 needs_review，不猜测或改用发布时间。
- 验证：标签 → 版本 → 对象 → 可达性及排除原因断言。

### AC-007：提交集合精确且固定

- 关联需求：REQ-007。
- Given：固定 B / H 的分支合并 DAG，含共享祖先、merge 与 dirty 文件；另有不可完整遍历的历史样本。
- When：分析 B 到 H，并在采集后修改实时 HEAD。
- Then：结果等于固定对象的可达差集，按对象去重，不按日期排除；dirty 不计入；实时变化使旧计划陈旧；截断不能当完整。
- 验证：与独立 Git 对象集合比较，保留对象清单和完整性字段。

### AC-008：提交信号与未知项可追溯

- 关联需求：REQ-008。
- Given：fix、feat、带 scope / !、合法两种 breaking footer、docs、普通消息、revert、普通 merge 和含类似 breaking 单词但不符合语法的消息。
- When：按已选 Conventional Commits 解析并保留原历史，分别以 major >= 1、0.x、预发布和首次版本策略计算；另测试未知或不适用的策略状态，不把它们当已获批准。
- Then：依据规范识别信号；breaking 不受 type 限制；普通词语不误判；major >= 1 与 0.x 使用不同映射；其他 type 不默认 patch；未知、merge、revert 与预发布相关证据留在复核清单，不丢失原对象证据。
- 验证：固定消息集的分类、映射和原因断言；不改历史，不调用模型 / 网络解释成事实；merge 不产生默认 bump，revert 不自动抵消，预发布不自动递增。

### AC-009：稳定版本、空集与未定策略

- 关联需求：REQ-009。
- Given：SemVer / Conventional Commits、稳定版与 0.x 映射、单一发布单元、预发布复核、首次版本手动输入及 bare-or-v 前缀已确认；隔离样本分别覆盖 1.4.2 与 0.4.2 基线、fix、feat、breaking、混合信号、空集、docs、非规范、预发布、无稳定基线、initialVersion、多个根、冲突与占用版本。
- When：以已确认规则请求建议，并分别检查稳定版、0.x、预发布、首次版本、未知 / merge / revert 和显式人工复核结果。
- Then：major >= 1 的前三项分别期望 1.4.3 / 1.5.0 / 2.0.0；0.x 的 fix / feat / breaking 分别期望 0.4.3 / 0.5.0 / 0.5.0；多信号取最高级且低位归零；预发布相关、基线 / initialVersion / 历史 / 证据缺口时 needs_review 且正式候选 null；空集 no_release；不擅自跳号、抵消、套用特殊规则或发行。
- 验证：样本表覆盖全部已收敛规则；候选始终是建议，人工确认不等于发布 / 完整性证明；规格检查通过不等于产品测试通过。

### AC-010：计划结构与可解释性

- 关联需求：REQ-010。
- Given：固定完整输入及策略，另有带未决项的输入。
- When：重复生成计划，在非模型入口打开证据 / 变更说明，并检查模型投影。
- Then：非模型必要字段完整且可回溯；变更说明确定性生成，未知 / breaking 单列，未提交功能不声称已交付；核心结果一致，不生成未来需求或日期。模型仅见白名单脱敏统计 / 候选，无完整计划、消息、证据或身份。
- 验证：契约与语义快照对比，忽略明确列出的采集时间 / 非语义 ID 字段。

### AC-011：人工调整不抹掉冲突

- 关联需求：REQ-011。
- Given：机器候选 major，用户尝试无理由、低版本、非法格式、已占用版本及合法调整。
- When：先不确认，再对当前指纹显式确认 / 调整，然后改变来源、连接代次、HEAD、基线、规则或人工输入。
- Then：未确认始终是待复核建议；无理由调整或非法目标被拒绝；低于规则建议保留冲突并 needs_review；合法选择保留原建议、人工选择 / 理由与证据；输入变化使确认失效，不授权发布或掩盖数据不足。
- 验证：输入校验、冲突状态与指纹绑定测试，不伪造用户身份。

### AC-012：显式、安全的报告导出

- 关联需求：REQ-012。
- Given：完整或待复核计划、外部目标、已存在文件、工作树内目标、共享 Git 目录、符号链接目标及磁盘写失败。
- When：预览、取消、选择路径、确认覆盖或触发失败。
- Then：仅明确允许且经必要确认的外部目标可写；取消无写入；越界 / 链接拒绝；失败不冒充成功；Markdown / JSON 都保留未决状态和快照身份。
- 验证：隔离目录内容 / 哈希、导出结构与失败恢复检查；无生产数据。

### AC-013：双模式只读与受限联网

- 关联需求：REQ-013。
- Given：合成仓库、工作树和 Git 目录建立前置快照，本地模式与受控 GitHub 测试连接分别配置，另注入缺对象和外部助手。
- When：发现、自动刷新、规划、取消和错误恢复；不执行报告导出。
- Then：两种模式均不改变工作树、索引、refs、标签、配置或远端资源；本地模式无 GitHub 请求，连接模式仅有已批准主机 / 仓库 / 用途的读取；无 clone / fetch、隐式补对象、发布或任意助手执行。不能仅凭“只读命令名”判通过。
- 验证：前后内容与引用对比、子进程和网络审计；不比较读取可能影响的访问时间。

### AC-014：可完成的宿主交互

- 关联需求：REQ-014。

- 验证：Codex 工作流端到端及适用键盘路径记录；当前接入与运行方式未定，本项未执行且相关实施阻塞。

- When：更新配置及重启会话。

- 关联需求：REQ-016。

### AC-017：元数据最小化与隐私

- When：检查、规划、复核、失败、非模型详情 / 导出、widget 状态保存和后续消息。

- 关联需求：REQ-018。

- Then：每次连接均需明确选择，不默认保存或沿用上次方式；取消不连接，会话模式不创建新持久秘密，库模式仅经用户选择保存应用管理项 / 引用。秘密不进入模型、普通配置、仓库、URL、命令参数、日志、错误或导出；缺安全入口禁用对应连接，缺安全库禁用保存且不自动改选会话。断开停止请求、清除活动会话秘密并废弃旧结果；删除仅针对应用管理项且明确报告失败，不删既有私钥 / 代理身份、不冒称服务端撤销。

- 关联需求：REQ-019。

- 验证：请求清单 / 重试预算、网络与副作用审计、受控图与完整性断言、断开取消及来源指纹；能力未验证时不标通过。

- 本轮只允许创建规格文档；后续实现、操作真实仓库、安装插件、外发数据或发布都不是本次授权的自动延伸。
