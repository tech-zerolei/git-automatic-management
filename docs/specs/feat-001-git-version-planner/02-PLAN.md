## 2. 数据流与执行边界

```text
用户启用批准范围
  → HostAdapter 提供已验证的开始 / 结束节点或手动刷新，选择本地 / GitHub 来源
  → GitHub 模式每次经 CredentialBroker 明确选择 PAT / SSH 与保管方式，确认目标，直接远端规划
  → DetectionCoordinator 合并任务、分配代次
  → GitReadAdapter 或 GitHubReadAdapter 能力 / 权限检查与最小元数据读取
  → RepoSnapshot + 完整性 / 陈旧状态
  → ReleaseAnalyzer 按已确认命名空间和 SemVer 建议可达标签基线，经非模型入口人工确认后固定 B/H
  → Conventional Commits 描述信号与项目 bump 策略分层，缺规则则 needs_review，不重写历史
  → 内部 VersionPlan + 确定性变更说明 + 来源 / 证据 + 风险（非模型）
  → NonModelReportView / PlanReview 对当前指纹显式确认或调整，保留冲突（非模型）
  → 用户另选外部目标后 ExportWriter 导出（非模型）
  → 独立 ModelSummaryProjector 仅投影白名单脱敏聚合统计 / 候选，隔离验证通过才可进入模型
```

### 2.1 最先验证的技术风险

1. 核实真实开始 / 结束事件及重复 / 丢失 / 异常退出语义、Git 子进程、取消、非模型详情 / 导出 / 安全凭据入口；不假设 Skill 具备生命周期能力。缺能力显示不可用 / 未执行并禁用相关路径，不扩为持续监听。
2. Git 版本和能力能否实现离线、无可选索引刷新与无外部助手读取。SPEC 第 14 节官方文档仅是依据，不是本机验证结果。
3. linked worktree 的实际 Git 目录可能不位于工作树内；批准工作树意味着是否允许访问其关联元数据必须在发现边界里显式说明，不扩大到任意其他路径。
4. 仓库配置 / 环境变量可能改变 Git 行为；受控环境必须排除不可信覆盖路径、外部监控、pager、隐式补对象及意外访问其他仓库。不得改用户配置来“修好”安全问题。
5. 报告写入有路径解析与竞态风险；确定宿主可提供的安全目标解析 / 文件句柄 / 原子替换方式。无法确保约束时拒绝导出，不降低到危险写法。
6. 核验 GitHub 认证类型、端点 / Git 读取操作与权限、主机验证、重定向、分页完整性、限流和取消；SSH 若无法在不 clone / fetch 的边界内提供所需提交图，明确限制，不能静默改走 PAT 或下载仓库。
7. 凭据、内部计划 / 证据 / 变更说明与模型上下文隔离；仅发经验证的白名单投影，审计工具、错误、widget 状态 / 标识、通知、follow-up 间接通道。脱敏不成立或不可审计时不发送 / 禁用，不以脱敏日志代替传输审计，不回退普通设置或聊天正文。

### 2.1.1 已选方案的能力核验表

此表是未来需要完成的技术验证，不是已实现兼容声明；Q-007 至 Q-009 不再列为用户偏好未知。两通道都属于已选方向，不能只完成 PAT 后把 SSH 项默认为不适用。

| 核验项 | PAT 通道 | SSH 通道 | 当前状态 / 不满足时 |
| --- | --- | --- | --- |
| 认证与只读边界 | 核验实际 PAT 类型、端点操作、仓库权限与主机范围 | 核验 SSH 身份 / 主机校验、受限调用与仓库绑定；不增加额外秘密或自动转为 API token | 未验证；拒绝越权，不自动切换通道或扩权 |
| 无本地克隆的完整远端规划 | 证明固定引用 / 对象、完整分页 / 图与基线可达差集；不能仅调用一个比较接口就宣称完整 | 在不 clone / fetch 的既定边界内证明同等数据可得；只列 refs 或认证成功不是提交图证明 | 未验证；不足则标 unsupported / needs_review 并保持相关交付未完成，提出明确约束冲突供用户决定，不悄悄放宽限制 |
| 每次连接保管选择 | 安全输入、仅会话和系统安全库两路径分别验证 | 验证既有私钥 / 代理安全引用、会话授权与系统库映射；不复制用户私钥来凑两种路径 | 未验证；不预选、不默认沿用，取消不连接，选项不支持则明确禁用，不自动改选 |
| 断开与删除 | 清除活动会话秘密、取消请求；单独删除仅作用于应用管理的已保存项 | 释放应用会话引用，不删除用户私钥 / 代理身份；单独删除仅针对应用管理项 | 未验证；报告清理失败，不冒称 GitHub 服务端撤销 |

技术提案应写出每项已证实能力、缺口和需用户重新确认的具体调整；不能将未来技术核验描述成已通过，也不能以“安全降级”替代两个已选通道的完整实现要求。

### 2.2 Git 访问建议

- 官方命令语义参考 SPEC 的 [S1]、[S2]、[S3]、[S6]。只为已核实能力建立读取操作；不预先声称某个最低 Git 版本适用。
- 通过可信可执行文件路径与参数列表启动，所有 refs 和路径先解析 / 校验，不直接拼接用户字符串、提交消息或 shell 命令。
- 机器状态采用稳定格式与 NUL 分隔；对象 ID 和路径按 Git 返回值处理，不假设 40 字符哈希或每行一个文件。
- 评估并验证禁用可选锁、lazy fetch、pager、外部 fsmonitor 等实际行为；仅禁用锁不等于阻止网络或助手执行。
- 提交图处理须明确 replace refs、graft / shallow 边界和缺对象的语义。无法保证原始完整图时返回不完整 / 不支持，不静默使用改写图得出正式版本。
- 使用只读元数据读取，不运行 hooks、外部 diff / textconv、源码构建、安装脚本或仓库内可执行文件。
