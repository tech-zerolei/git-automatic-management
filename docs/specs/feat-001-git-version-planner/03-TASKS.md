## 2. 每个任务必须补齐的执行卡

接到明确实施要求后，在项目实际任务工具或本文件关联记录中补齐：

1. 当前规格 / 计划版本及就绪确认记录。
2. 实际代码基线、文件范围与上游产物；新增文件注明拟新增。
3. 可检查产物：代码、测试、文档或已核实能力结论，不只写“研究”。
4. 真实运行命令或明确人工操作步骤、所需环境、输入样本及 AC 判据。
5. 实际执行时间、代码版本、预期 / 实际结果、证据位置与限制。
6. 失败后的停止范围、问题记录、负责人和恢复条件。

当前不存在项目测试脚本，不能提前填 `npm test`、框架命令或 CI 链接。任务验证以 SPEC 中对应 AC 为准；搭好测试入口后再把真实命令写入执行卡和 ACCEPTANCE。
